3. **Python 3.11** in a uv venv. tau-bench needs >= 3.10.
4. **tau-bench as a pinned git dependency** in pyproject.toml (commit 59a200c), so `pip install -e .` works from scratch. A local clone in `vendor/` is kept only for reading code and historical trajectories.
5. **`think` tool -> tier `special`** (no gate). It does not touch the database.
6. **Split** (adopted): `fit` = 250 tasks sampled from `train` by task index with seed 0; `cal` = the other 250 `train` tasks plus all 20 `dev` tasks (270 total); `test` = the tau-bench `test` split (115), used only for the live evaluation. Reason: `dev` alone (20 tasks) is too small for alpha=0.02 (needs N >= 49).
7. **Budget** (Youssef, 2026-10-13: "no escatimes en tokens ni nada"): no spending cap. `MAX_USD` stays in the config as a runaway guard only, set to 1000 USD; it exists so a bug cannot loop forever, not as a budget.
8. **Provider and models** (adopted after probing; the environment has no Anthropic/OpenAI keys, it has a z.ai Anthropic-compatible endpoint): all calls go through `ANTHROPIC_BASE_URL` (z.ai) with `ANTHROPIC_AUTH_TOKEN`, provider `anthropic` in litellm. Agent = `glm-5.3`, signals = `glm-5.3` (same model as the agent, per plan 4.4), simulated user = `glm-5.3-flash`. Verified live: both models answer and emit tool calls through litellm (notes/env_check.md).
9. **Cost accounting**: litellm has no price entry for GLM models (`response_cost` is None), so every run records raw token counts per model, and USD is computed later from a price table in the config with its source date. tau-bench's own user-cost field is wrong (see env_check) and is ignored.
10. **Note on default behavior of the endpoint**: glm models emit `thinking` blocks by default. litellm maps tool calls fine (verified). If thinking ever makes a response come back without a tool call, the agent treats it as a `respond` action, same as any model.
11. **Agent model = glm-5.3-flash** (2026-10-13, after two 20-task pilots, evidence in results/collect/): glm-5.3 errs on only 4% of gated actions on train (1/25, too few positives to fit anything), glm-5.3-flash errs on ~12% (2/17, near the historical sonnet-3.5 rate of 21%), at a tenth of the price. Signals are saturated near 1.0 for both models (verbalized 1.0 on 14/15 resp. 16/17 rows; agreement 1.0 on almost all) - recorded as a finding per plan section 4.4, not a defect. All three policies will be compared under this same agent model.
12. **Two pilot datasets discarded and archived** (rows_glm53_pilot.jsonl, rows_flash_pilot_prelabelingfix.jsonl, rows_smoke_prelabelingfix.jsonl): the flash pilot ran with the labeling/verbalized code as it was before the adversarial-review fixes, so its labels cannot be mixed with the corrected collection. Kept as evidence for decision 11 only.
13. **Phase 6 endpoint = regular z.ai API for all five configurations** (2026-10-14): the run started on the coding-plan endpoint (flat-rate subscription, no per-token billing, but rate-limited) and was switched to the regular API after a rate-limit conflict. Because the switch point lined up with task order, endpoint and task were confounded (ai_review_log case 10), so all five configurations were completed in full on the regular API (2300 trajectories) and the main report uses only that run. The coding-plan run (confirm_all 460, fixed_threshold 369, calibrated 250 trajectories) is kept and reported separately in results/report_coding_plan.md, with confirm_all compared across endpoints in the main report.
14. **One run per distinct lambda, not per alpha** (2026-10-14): conformal risk control gave the same lambda (0.6678) for alpha 0.10 and 0.20, so those two rows share one set of 460 trajectories instead of running the same configuration twice (ai_review_log case 6).
15. **Retry policy** (2026-10-14): an explicit backoff ladder (4 to 120 s) on top of two litellm retries absorbs sustained z.ai rate limits (case 7); balance-exhaustion errors fail fast instead of retrying, because no backoff fixes them (case 11).
16. **Credentials**: the launch script maps `ZAI_API_KEY` into the child process environment at launch; no key is ever written to a file (case 8). Temperature-0 calls are cached on disk under `.cache/llm`, keyed by full payload, which is what makes the report reproducible without re-paying.
